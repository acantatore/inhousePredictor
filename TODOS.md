## P2 — Ship before general availability

- [ ] **Forecast Question pivot epic** — evolve the product from market-first into a forecasting-first system while keeping the existing market engine as a secondary advanced module. Scope: make `Forecast Question` the canonical object, store forecast revisions append-only, embed rationales with forecasts, use Brier score as the only official score, derive calibration/coverage as analytics, require notification trigger/idempotency tests, and keep external Polymarket/Kalshi-style signals as read-only snapshot overlays. Why: this locks the strategic direction from `deep-research-report.md` into an implementable milestone instead of letting the repo drift back into mixed market/scoring semantics. Depends on: no blocking implementation dependency, but future work should treat this as the parent epic for scoring, rationale, notification, and external-signal tickets.
- [ ] **Forecast projection layer** — add a dedicated projection/cached-read layer for the forecasting pivot that owns latest active contributor forecasts, official internal forecast calculation, and contributor snapshot-at-close reads. Why: append-only history is the source of truth, but dashboards, notifications, and scoring should not each recompute from raw revision history. This protects correctness, performance, and DRY implementation. Depends on: `ForecastQuestion` / `ForecastRevision` domain and the shared `forecast` aggregation module. Priority: P2.
- [ ] **Sell/Exit mechanism** — users can only BUY shares, never sell. CPMM sell is the inverse: add `shares` back to the relevant reserve, recalculate the other side, credit collateral to user balance. Add `sell_yes` / `sell_no` trade sides. Update position to subtract shares. Effort: S. Depends on: payout idempotency fix (shares must be tracked correctly).
- [ ] **Structured logging (slog)** — replace chi.middleware.Logger with Go 1.21 `slog`. Log at trade execution: trade_id, market_id, user_id, cost, shares, price_before, price_after. At payout: market_id, total_collateral, winners, payout_per_share. At webhook: source IP, HMAC result.
- [ ] **Market list pagination** — `market.List` returns all markets with no LIMIT. Add LIMIT 50 + keyset pagination (`?cursor=<last_created_at>`).
- [ ] **Input validation** — question max 500 chars, description max 2000 chars, evidence_url must be valid URL, password min 8 chars. Add `internal/validate/validate.go`.
- [ ] **Enforce creator trading restriction** — creator trading is now a locked product rule: creators cannot trade their own markets. Enforce server-side in the trade path, return a safe 403/409-style product error, explain the restriction in market detail and create-market review states, and add regression coverage for creator self-trading attempts.
- [ ] **closes_at < resolves_at validation** — market service currently allows `closes_at > resolves_at` (market resolves before it closes). Add validation in `market.Create`.
- [ ] **Graceful shutdown** — catch SIGTERM, call `server.Shutdown(ctx)` with 30s drain. In-flight WS connections close cleanly. Currently hard-drops all connections on restart.
- [ ] **Frontend route / API namespace split** — the Vite dev app and the backend both use paths like `/markets` and `/markets/:id`, so direct browser navigation or refresh can return raw API JSON instead of the SPA shell.
