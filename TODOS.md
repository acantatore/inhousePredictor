# TODOS

## P1 — Must ship before first users

- [ ] **Fix: closes_at enforcement in trade path** — trades currently accepted forever after market deadline. Add `closes_at < NOW()` check inside `trade/repository.go:execute()` before CPMM. Return 400 "market closed".
- [ ] **Fix: payout idempotency** — `trade.Payout()` can be called twice, doubling all winner balances. Add `payout_at TIMESTAMPTZ` to markets table. Payout only runs when `payout_at IS NULL`, sets it atomically (migration 002).
- [ ] **Fix: dispute deadline enforcement** — `market.Dispute()` silently inserts a dispute row even after `dispute_deadline` has passed. Check deadline before insert, return 400 "dispute window closed".
- [ ] **Fix: serialization error handling** — concurrent trades on same market return raw pgx error `40001` to user. Detect this code in TradeHandler, retry up to 3×, then return 409 "market is busy, please try again".
- [ ] **Fix: remove K column from pools table** — K drifts due to float64 arithmetic over thousands of trades. Remove `k` column, compute `K = yes_reserve * no_reserve` inline in Go. (migration 003)
- [ ] **Fix: duplicate email error** — `user.Create()` returns raw Postgres unique violation on duplicate email. Detect error code `23505`, return 409 "email already registered".
- [ ] **golang-migrate embedded** — schema currently only applies on fresh postgres container. Embed golang-migrate in server binary, run on startup before serving traffic.
- [ ] **BOOTSTRAP_ADMIN_EMAIL env var** — no way to create the first admin except raw SQL. On startup, if env var is set and no admin exists, promote that user.
- [ ] **CPMM unit tests** — `internal/cpmm/cpmm_test.go`. Test: K invariant holds after BuyYes/BuyNo, price symmetry, price never exceeds 1.0, payout sums to total collateral, BuyYes then BuyNo is not fully reversible (slippage).
- [ ] **Integration tests** — testcontainers-go for real Postgres. Test: market creation debits creator, trade execution atomicity, payout correctness, insufficient balance rejection.
- [ ] **Admin dispute resolution workflow** — disputed markets can be created but cannot be resolved inside the app. Add an admin-only endpoint/service path to accept or reject disputes, define the allowed terminal states (`resolved`, re-resolved, or `cancelled`), record `resolved_by`/`resolved_at`, and cover the lifecycle with integration tests. Depends on: payout idempotency fix and standardized error responses.
- [ ] **Authenticated WebSocket + origin allowlist** — `GET /ws` is currently public and `CheckOrigin` accepts any origin. Require the same auth boundary as the HTTP API, allow only approved company origins, support both all-market and market-scoped subscriptions, and add handshake/origin integration tests.
- [ ] **Shared API error/response layer** — handlers currently mix raw `http.Error`, leaked DB errors, and duplicated JSON helpers. Add a small internal HTTP helper with typed domain errors so duplicate email, serialization retry, auth failures, validation errors, and not-found cases return consistent JSON and status codes.

## P2 — Ship before general availability

- [ ] **Forecast Question pivot epic** — evolve the product from market-first into a forecasting-first system while keeping the existing market engine as a secondary advanced module. Scope: make `Forecast Question` the canonical object, store forecast revisions append-only, embed rationales with forecasts, use Brier score as the only official score, derive calibration/coverage as analytics, require notification trigger/idempotency tests, and keep external Polymarket/Kalshi-style signals as read-only snapshot overlays. Why: this locks the strategic direction from `deep-research-report.md` into an implementable milestone instead of letting the repo drift back into mixed market/scoring semantics. Depends on: no blocking implementation dependency, but future work should treat this as the parent epic for scoring, rationale, notification, and external-signal tickets.
- [ ] **Forecast projection layer** — add a dedicated projection/cached-read layer for the forecasting pivot that owns latest active contributor forecasts, official internal forecast calculation, and contributor snapshot-at-close reads. Why: append-only history is the source of truth, but dashboards, notifications, and scoring should not each recompute from raw revision history. This protects correctness, performance, and DRY implementation. Depends on: `ForecastQuestion` / `ForecastRevision` domain and the shared `forecast` aggregation module. Priority: P2.
- [ ] **Sell/Exit mechanism** — users can only BUY shares, never sell. CPMM sell is the inverse: add `shares` back to the relevant reserve, recalculate the other side, credit collateral to user balance. Add `sell_yes` / `sell_no` trade sides. Update position to subtract shares. Effort: S. Depends on: payout idempotency fix (shares must be tracked correctly).
- [ ] **Structured logging (slog)** — replace chi.middleware.Logger with Go 1.21 `slog`. Log at trade execution: trade_id, market_id, user_id, cost, shares, price_before, price_after. At payout: market_id, total_collateral, winners, payout_per_share. At webhook: source IP, HMAC result.
- [ ] **Market list pagination** — `market.List` returns all markets with no LIMIT. Add LIMIT 50 + keyset pagination (`?cursor=<last_created_at>`).
- [ ] **Input validation** — question max 500 chars, description max 2000 chars, evidence_url must be valid URL, password min 8 chars. Add `internal/validate/validate.go`.
- [ ] **Enforce creator trading restriction** — creator trading is now a locked product rule: creators cannot trade their own markets. Enforce server-side in the trade path, return a safe 403/409-style product error, explain the restriction in market detail and create-market review states, and add regression coverage for creator self-trading attempts.
- [ ] **closes_at < resolves_at validation** — market service currently allows `closes_at > resolves_at` (market resolves before it closes). Add validation in `market.Create`.
- [ ] **Graceful shutdown** — catch SIGTERM, call `server.Shutdown(ctx)` with 30s drain. In-flight WS connections close cleanly. Currently hard-drops all connections on restart.
- [ ] **Frontend route / API namespace split** — the Vite dev app and the backend both use paths like `/markets` and `/markets/:id`, so direct browser navigation or refresh can return raw API JSON instead of the SPA shell. Move API traffic under a dedicated prefix (for example `/api/*`) or add a routing strategy that preserves React Router navigation without colliding with backend endpoints.
